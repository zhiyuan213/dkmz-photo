## 一、产品定位

**一句话**：帮考生 3 分钟做出符合报名要求的证件照——选底色 + 选尺寸 → 自动裁剪构图 → 一键换底 → 付费解锁高清无水印。

> **实现修订（2026-10-14）**：原设计"选考试 → 自动套用规格"，实际开发发现考试场景太多、且多数考试规格高度重叠，遂**去掉「场景/考试」维度**，
> 改为**用户直接选底色 + 直接选尺寸**；规格知识（哪个考试用哪个尺寸、体积上限）改以**尺寸项上的场景标注 `usedBy` + 从严体积说明**承载，既不丢专业性，又大幅简化交互。

- **目标用户**：所有需要线上报名的考生（教资、考研、公考、四六级、计算机等级、法考、一建二建、护士、执业医师、高考…）
- **与主站的联动**：主站负责"什么时候要报名"（节点倒计时 + 订阅提醒），本产品负责"报名要的照片帮你做出来"——两者同一批用户，可互相跳转导流
- **类目必须落在**：`工具 → 图片处理`（个人主体类目硬约束，也是开通虚拟支付的前提）

## 二、MVP 范围（第一版只做一条主链路）

```
上传照片 → 选底色 + 选尺寸（自动套用像素/体积/构图规则）→ 人脸检测 + 自动裁剪构图
```

**第一版明确不做**（留到第二版）：换正装、美颜磨皮、批量处理、线下打印快递、多语言。

判断标准：**能不能跑通"卖出第一单"**。功能多少不关键。

## 四、规格数据库（产品的核心资产）

> ⚠️ **重要**：以下数据来自公开资料整理，**各类考试每年可能调整**。上线时必须以「当年官方报名公告」为准，产品内需展示"数据更新时间"与免责说明，并做成**后台可配置**（不能写死在代码里）。

### 4.0 最终数据模型（v2，与代码一致）

去掉"场景/考试"维度后，规格库只剩两张表：

- **底色 `backgrounds`（4 色）**：白 `#FFFFFF` / 蓝 `#438EDB` / 红 `#B80202` / 浅蓝 `#E6F0FA`（红底已恢复，因为不少考试仍要求红底）
- **尺寸 `sizes`（10 个）**：每个尺寸项携带完整规格知识——
  `mm` 物理尺寸、`px` 像素、`sizeRule`（exact/range）、`minSizeKB`/`maxSizeKB` 体积区间、
  `sizeNote` 人类可读说明、`usedBy` 适用考试标注、`cropFaceRatio`（抠图人脸占比，个别尺寸如驾照需更小）。

**体积上限一律"取最严"**：同一个像素尺寸下若多个考试要求的 KB 区间不同，取交集/最严值（例如一寸记 20~100KB），
这样一张成品可通用于该尺寸下所有考试，避免用户反复重做。这个取舍是产品核心卖点的一部分。

**结构升级怎么生效**：种子 JSON 带 `schemaVersion`，后端启动时比对 DB 中版本，不一致则全量重导（`syncSchemaIfNeeded`）；
变更历史遗留的 `preset` / `exam` 类型记录会被 `purgeRetiredKinds` 清理。

### 4.3 构图规则（自动裁剪的依据）

- 免冠正面、露出双耳与额头
- 头顶预留少量空白、下巴位于画面下方约 1/3 处
- 禁止自拍镜像、美颜过度、头饰遮挡五官

## 五、技术方案

### 5.1 人脸检测与自动构图（免费，端上）

- 用微信官方 **VisionKit**：`wx.createVKSession({ track: { face: { mode: 2 } } })`（**静态图片模式**）
- 通过 `session.detectFace({ frameBuffer, width, height, sourceType: 1 })` 拿到**人脸框 + 五官关键点**
- 依据 4.3 的构图规则反推裁剪框（人脸框按比例外扩、上移），实现"自动居中、自动留白"
- 基础库要求 2.25.0+（需做低版本兼容提示）
- ✅ 免费、端上运行、无需上传照片

### 5.2 人像抠图（关键难点，两条路线）

| 方案 | 说明 | 成本 | 隐私 | 结论 |
|---|---|---|---|---|
| **A. 端上推理（推荐）** | `wx.createInferenceSession` 跑开源模型 MODNet（onnx），模型文件放 CDN 供小程序下载缓存，本地推理出 alpha 蒙版 → 合成新底色 | **0 元/次** | 原图不出手机，最好 | 首选 |
| B. 云端抠图 API | 上传照片到服务端/第三方 API 抠图 | 按次计费 | 需上传用户照片，隐私政策要求高 | 降级备用 |

**建议**：先做 A；遇到低端机性能/兼容问题，再对特定机型降级到 B。

### 5.3 合成与导出

- 离屏 canvas（`wx.createOffscreenCanvas`）按规格绘制：纯色底 → 人像层 → 输出指定像素
- `canvasToTempFilePath` 导出，再按目标 KB 压缩（`wx.compressImage` 或 canvas 质量控制）
- 水印预览：预览图上端上叠加半透明水印（**不上传**），付费后重新导出无水印高清

### 5.4 服务端（复用现有能力）

- 复用**微信云托管**（新开一个服务或新环境），只承担三件事：
  1. 规格库下发（后台可配置，随时改）
  2. 订单 + 虚拟支付签名/下单（可直接抄「考试倒计时」的 `pay_order` + 发货推送链路）
  3. 发货回调解锁（校验签名 → 标记订单已支付 → 前端拉取高清图）
- 静态资源：抠图模型文件放 CDN

### 备案变更要点（2026-10 核实）
- **改名 / 改服务内容不是"重新备案"，而是走「变更备案」**——入口在 mp 后台【账号设置 → 基本信息 → 小程序备案 → 变更】；
- **顺序不能颠倒**：备案订单里的"小程序名称"字段是系统按当前实际名称自动抓取的（灰色不可改），所以必须**先在后台提交改名/改类目并通过审核，再发起变更备案**；
- **时效**：平台初审 1–2 个工作日 + 各省通信管理局 1–20 个工作日（与首次备案相同，具体以实际为准）。**这是全链路里最长的一段，越早提交越好**；
- **7 日时限（重要坑）**：备案信息与小程序实际信息不一致时，会收到工信部比对触发的"变更备案提醒"，要求 **7 日内**更新，逾期可能被警告/处置、影响小程序正常运营；
- **一次改完**：改名和改类目一起做、只发起一次变更备案，避免反复走管局；
- **开发不受阻塞**：变更备案期间照常写代码、真机调试；只是"提审发布"建议等备案通过后再做（首次上线必须有有效备案）。
