### 「一次返回 8 张」的出处

美颜接口 `products/41079` 的**公开返回示例**是这样的：

```json
{
  "ret": 0,
  "body": {
    "fid": "string",
    "check_result": [{ "code": 0, "desc": "string" }],
    "idphoto_general_plain":   ["string"],
    "idphoto_enhance_plain":   ["string"],
    "idphoto_general_beautify":["string"],
    "idphoto_enhance_beautify":["string"]
  }
}
```

四个数组 = **普通版/增强版 × 原图/美颜**。**「8 张」极可能是这几个数组的元素组合**
（例如 2 档尺寸或 2 种底色 × 4 类）。⚠️ 这是**推断，不是确认**——
试用第一件事就是数清楚每个数组里到底几张、分别是什么（底色？尺寸？版式？），
因为这决定了我们的商品该怎么定义、卖点怎么写。

### 鉴权（两个平台不一样，注意）

- **阿里云（推荐）**：支持「简单身份认证」，Header 直接带
  `Authorization: APPCODE <你的AppCode>`，不需要算签名 → 集成最简单。
  也支持签名认证（AppKey & AppSecret）。
- **腾讯云网关**：需要**签名**，Header 形如
  `Authorization: {"id":"AKIDxxx","x-date":"Mon, 19 Mar 2018 12:08:40 GMT","signature":"xx="}`，
  用云市场分配的密钥计算签名，还要带 `request-id: uuid`、`X-Requested-With: XMLHttpRequest`，
  `Content-Type` 可能是 `application/x-www-form-urlencoded`。
  → **麻烦得多，除非腾讯云那侧价格明显更好，否则走阿里云。**
- 两个平台的网关都有可选头 `X-Auth-Code` / `X-Channel-Id`。

**对我们最重要的两点**：

1. **`img_base64` 只在高级版（¥1/次）上有**。标准版的示例只给 `img_url`。
   我们的用户照片在服务端内存里（不上传图床），所以**大概率必须走高级版**——
   除非确认标准版也吃 base64，或我们另做一个带签名的临时图床 URL。→ 成本按 **¥1/次** 先算。
2. **高级版「预览不收费」跟我们的模式天然对齐**：可以先把 8 张带水印预览给用户看，
   用户付费后再调「获取无水印图」那个子接口。若"预览"确实不扣费，
   那么**免费预览环节零成本、付费才产生成本**。→ 这条必须跟服务商书面确认。

## 2. 差价模型（含一个必须先解决的定价冲突）

⚠️ **我们有价格倒挂风险。** 现有虚拟支付商品（`application.yml` 的 `XPHOTO_GOODS`）：

| goodsId | 价格 | 权益 |
|---|---|---|
| `photo1` | **¥3.90** | 单张高清无水印导出 |
| `photo3` | **¥6.90** | 规格套装（3 张） |
| `vip1` | **¥19.90** | 年会员（1 年不限保存次数） |

如果新的"8 张高级功能"只收 **¥2~3**，就比**单张**（¥3.90）还便宜 ——
用户只会买这个，`photo1` 直接被打垮。

**建议**：这个功能定价不要低于 ¥3.90。两条路：
- 定为 **¥4.90 ~ ¥5.90** 的独立商品（让"8 张"明显高于"1 张"），或
- 直接**替换掉 `photo3`**（现在 3 张 ¥6.90，用 8 张 ¥6.90 替代，加量不加价，更好卖）。

单次毛利（按高级版 ¥1/次）：

| 售价 | 拍博士成本 | 毛利 | 毛利率 |
|---|---|---|---|
| ¥2.90 | ¥1.00 | ¥1.90 | 66% |
| ¥3.90 | ¥1.00 | ¥2.90 | 74% |
| ¥5.90 | ¥1.00 | ¥4.90 | 83% |

若能用上标准版（¥0.06/次），毛利几乎翻倍 —— 所以**"能不能传 base64 / 能不能喂图床 URL"是成本关键分叉点**，
值得专门问一次服务商。

**另外**：这类按次成本的付费功能**绝对不能挂进 `vip1` 年卡"不限次数"**，
否则重度用户会把毛利吃穿。要么年卡不含此功能，要么年卡给固定张数。

## 3. 试用获取步骤（可执行）

1. 登录**阿里云**账号 → 云市场 → 搜索「拍博士 证件照」→ 找到
   **【拍博士】证件照标准制作**（`cmapi00066968`）→ 选「免费试用」套餐开通
   （商品页有「免费试用」版本，有用户评论就是走的这个套餐）。
2. 同时开通 **【拍博士】证件照制作高级版（预览不收费）**（`cmapi00066969`）免费试用 ——
   换装和 `img_base64` 在这个商品里。
3. 进入**云市场控制台 → 已购买的服务 → 该商品 → 查看密钥**，拿到
   **AppCode**（简单认证只需这个）和 **AppKey / AppSecret**。
4. 顺手把商品页的**「接口文档」下载下来**（腾讯云那侧有一份
   《腾讯云证件照接口使用说明.pdf》）。这份文档能一次性确认：`product_id` 规格表、
   `clothes_id` 换装编码表、各子接口路径、以及返回数组的真实含义。
5. 用本文配套脚本跑真实照片（见下节）。

```bash
export PAIBOSHI_APPCODE=你的AppCode
# 先干跑，确认请求构造正确、不消耗配额
python tools/paiboshi_probe.py --image 一张自拍.jpg --dry-run
# 真跑，结果落到 ./paiboshi-trial/
python tools/paiboshi_probe.py --image 一张自拍.jpg --out ./paiboshi-trial
```

## 4. 验收标准（跑完逐个打勾）

对照现有 BDA 链路和端上链路一起看：

**质量**
- [ ] **数清楚返回到底几张、分别是什么**（底色？尺寸？增强前后？美颜前后？）——决定卖点怎么写
- [ ] 换装贴合：领口、肩线、发丝边缘**无断裂、无鬼影、不漏底**（这是换装最容易翻车的地方）
- [ ] 抠图/换底质量 **≥ 现有 BDA 链路**（同一张图对比）
- [ ] 美颜："不失真不假颜"是否真的成立（我们自己在美肤上踩过「泥巴脸」的坑）

**鲁棒性**
- [ ] 普通手机自拍（非专业影棚）的出图可用率 —— **目标 ≥ 80%**，低于这个值不值得上
- [ ] 侧脸、戴眼镜、额头被头发遮挡、多人同框 时的行为（有无 `check_result` 可读的失败语义）
- [ ] 换装对**构图/姿态的要求**有多严（是否需要用户重新拍、能不能给引导语）

**工程**
- [ ] 单次耗时（网关公开数据 ~2.2s）端到端是否 ≤ 8s
- [ ] 返回分辨率是否 ≥ 我们的目标规格（如 480×640 / 295×413），
      且**能通过我们自己的规格校验**（像素、体积、比例）
- [ ] 返回是 base64 还是 URL、体积多大（影响我们服务端内存与超时）

## 5. 合规：必须同步改的三处（否则提审会被打回）

现状：隐私政策只把**腾讯云·人像分割**列为唯一照片受托处理方，并明确写了
「**也不会向任何第三方共享、转让或公开披露你的信息**」。引入拍博士（深圳市六六六网络服务有限公司）后这句话**直接不成立**。

1. `miniprogram/pages/privacy/privacy.wxml`
   - 第一条（数据收集说明）、第三条（信息共享）
   - 第四条「第三方与开源组件」补入新受托方：**深圳市六六六网络服务有限公司**，
     说明"照片会上传至其服务用于抠图/换装/排版"，并写清处理目的与范围
   - 那句"不向任何第三方共享"必须改写
2. mp 后台《用户隐私保护指引》—— 同步新增受托方与处理目的
3. `miniprogram/utils/legal.js` 的 `UPDATED_AT` 同步更新日期

**不需要**加 `request` 合法域名 —— 我们走**服务端调用**（密钥只放云托管环境变量），端上不直连。
服务类目「工具→图片处理」不受影响。云市场购买是正规渠道（有商品协议、对方开票），合规性无问题。

## 6. 集成设计（等验证通过再动手）

照搬现有 BDA 那套，最小改动：

```
backend/src/main/java/com/dkmz/photo/service/
  ├─ PaiboshiClientProvider.java   # 密钥仅存环境变量，单例 BdaClient 式复用
  ├─ PaiboshiSegmentService.java   # 换装 / 多图制作
  └─（沿用）SkinBeautyService、PortraitCompositeService 做后处理
controller/
  └─ IdPhotoController.java        # 加一个 /api/photo/advanced 之类的入口
```

环境变量（不配置 = 功能关闭，不影响其他接口）：

| 变量 | 说明 |
|---|---|
| `PAIBOSHI_ENABLED` | 总开关 |
| `PAIBOSHI_APPCODE` | 阿里云云市场 AppCode（简单认证） |
| `PAIBOSHI_APPKEY` / `PAIBOSHI_APPSECRET` | 若要签名认证 |
| `PAIBOSHI_ENDPOINT` | 覆盖接入地址（默认阿里云 `idsuipai.market.alicloudapi.com`） |
| `PAIBOSHI_PRODUCT_ID` / `PAIBOSHI_CLOTHES_ID` | 默认规格 / 换装编码 |

**失败必须回退**：拍博士任何失败 → 回退现有 BDA 云端精修 → 再回退端上 MODNet。
沿用现有「出片不中断」原则。

**先验证连通性**：云托管容器能否直连 `idsuipai.market.alicloudapi.com`（https）。
我们接 BDA 时撞过 PKIX 证书问题、最后走了内网 endpoint，所以这一步别跳过。

**防刷/限额**：沿用 10-13 加的 `X-WX-OPENID` 强制 + 滑动窗口限流，
并给这个按次计费的功能单独设**更严的额度**（每次调用都真花钱）。
